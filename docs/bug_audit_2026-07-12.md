### 1. [ML_RL_Trader_template.mq5:461] CalcSLTP indexes ATR handle array assuming ATR_PSTEP==1 and ATR_PMIN<=14 — wrong ATR period silently used for SL/TP, or array-out-of-range crash

- [ ] **fix** · stage: export-ea
- **Trigger:** Export any model trained from an 'extras' collector dataset (e.g. existing models rl_uj_extra or rl_uj_h4_extras_2, whose params.json sets ATR_PMIN=6, ATR_PSTEP=4 — already baked into mt5_files/packages/rl_uj_extra/MQL5/Include/rl_uj_extra_config.mqh lines 600-602), compile the generated EA, run it, and let it open a trade. If a future dataset uses ATR_PMIN>14, the index goes negative and the EA dies with an 'array out of range' critical error on the first OpenPosition call.
- **Fix sketch:** In CalcSLTP (ML_RL_Trader_template.mq5:461) replace g_h_atr[14 - ATR_PMIN] with the dedicated fixed-period handle g_h_atr14_ref, which RL_InitIndicators already creates as iATR(symbol, tf, 14) (RL_Indicators.mqh:465) and validates as a critical handle (line 519): `if(CopyBuffer(g_h_atr14_ref, 0, 1, 1, atr_buf) <= 0) { ... }`. This is strictly better than computing a step-aware index because period 14 may not even lie on the PMIN/PSTEP grid. Apply the same one-line change to the already-exported packages mt5_files/packages/rl_uj_extra/MQL5/Experts/rl_uj_extra_EA.mq5:461 and mt5_files/packages/rl_uj_h4_extras_2/MQL5/Experts/rl_uj_h4_extras_2_EA.mq5:461 (and recompile), or re-export them from the fixed template.
