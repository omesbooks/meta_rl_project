Monte Carlo คืออะไร — และทำไมมีทั้งในหน้า Train และหน้า Backtest

เข้าใจกระบวนการ Monte Carlo ตั้งแต่แนวคิดพื้นฐาน กลไกที่ระบบใช้จริง ไปจนถึงความต่างสำคัญระหว่าง MC ตอนเทรน (คัดกรอง recipe) กับ MC ตอน backtest (ตัดสินขนาดทุนก่อน live)

1) Monte Carlo คือกระบวนการอะไร

Monte Carlo method ตั้งชื่อตามคาสิโนในโมนาโก — หลักการมีประโยคเดียว:

เมื่อคำนวณคำตอบตรงๆ ไม่ได้หรือยากเกินไป ให้ "สุ่มจำลอง" สถานการณ์นั้นหลายพันรอบ แล้วอ่านคำตอบจาก "การกระจาย" ของผลลัพธ์แทน

ผลที่ได้ไม่ใช่ตัวเลขเดียว แต่เป็นช่วงความน่าจะเป็น เช่น แทนที่จะบอกว่า "Max DD = -12.7%" (ค่าเดียวจากเหตุการณ์เดียว) Monte Carlo ตอบว่า "Max DD มัธยฐาน -12.7%, มี 5% ของโลกที่เป็นไปได้ที่ลึกกว่า -16.5%, และ 16% ของโลกทั้งหมดชน hard stop" — ข้อมูลแบบหลังใช้ตัดสินใจเรื่องเงินได้จริงกว่ามาก

ประมาณค่า π ด้วยการโปรยจุด

สุ่มจุดลงในสี่เหลี่ยมที่มีวงกลมอยู่ข้างใน นับสัดส่วนจุดที่ตกในวงกลม → ยิ่งโปรยมาก ค่ายิ่งลู่เข้า π/4 — ไม่ต้องรู้สูตรอินทิเกรตเลย

2) ทำไม backtest ครั้งเดียวถึงไม่พอ

ผล backtest หนึ่งครั้งคือ trades ชุดหนึ่ง เรียงตามลำดับที่บังเอิญเกิดครั้งเดียว สมมุติระบบแพ้ 8 ไม้ติดกันช่วงกลางปี — ถ้าความซวยชุดเดียวกันนี้มาต้นปีแทน (ซึ่งเป็นไปได้พอๆ กัน) equity จะดิ่งตั้งแต่ยังไม่มีกำไรสะสมมารองรับ → Max DD ลึกกว่าเดิมมาก ทั้งที่เป็น "trades ชุดเดียวกันเป๊ะ"

คำถามเรื่องเงิน (ตั้ง risk เท่าไหร่ / hard stop ตรงไหน / ทุนพอไหม) จึงห้ามตอบจากลำดับเดียว — ต้องตอบจากการกระจายของทุกลำดับที่เป็นไปได้ นั่นคืองานของ MC

3) กระบวนการที่ระบบใช้จริง — 2 probes

Probe A: Order Shuffle → การกระจายของ Drawdown

trades = [ +0.8%, -0.5%, +1.2%, -0.3%, ... ]   # ผลต่อ trade จากการรันจริง

ทำซ้ำ 1,000 รอบ:
    สลับลำดับ trades แบบสุ่ม
    สร้าง equity curve ใหม่จากลำดับนั้น (ทบต้น)
    บันทึก Max Drawdown ของเส้นนั้น

ผลลัพธ์: การกระจายของ DD 1,000 ค่า
    → median / 95% worst-case / worst / P(ชน hard stop)
ข้อเท็จจริงทางคณิตศาสตร์: กำไรปลายทางไม่เปลี่ยนตอนสลับลำดับ เพราะผลคูณ (1+r₁)(1+r₂)... สลับที่ได้ — สิ่งเดียวที่เปลี่ยนคือ เส้นทางระหว่างทาง (drawdown path) ระบบจึงรายงานเฉพาะ DD

Probe B: Skip Trades → Profit Retention (เกณฑ์สไตล์ SQX)

ทำซ้ำ 1,000 รอบ:
    สุ่มตัด trades ทิ้ง 10% (ค่า MC Skip %)
    คำนวณกำไรรวมจาก trades ที่เหลือ

ผลลัพธ์: การกระจายของกำไร
    → retention = กำไร p95-แย่สุด ÷ กำไรเต็ม   (ควร ≥ 70%)
    → P(flip)  = โอกาสที่กำไรพลิกเป็นขาดทุน    (ควร < 5%)

Probe นี้ตอบคำถาม "edge กระจุกอยู่ไม่กี่ไม้หรือเปล่า" — ถ้าตัด trade ทิ้งแค่ 10% แล้วกำไรพังหมด แปลว่ากำไรทั้งระบบพึ่ง trade ทองไม่กี่ตัว = เปราะมากใน live (ต่างจาก Probe A: การ "ตัด" trades ทำให้กำไรเปลี่ยนได้จริง จึงวัด retention ได้)

4) MC ใน Train vs MC ใน Backtest — ต่างกันยังไง

ระบบรัน Monte Carlo ใน 2 จุด ด้วยจุดประสงค์คนละอย่าง ความต่างที่สำคัญที่สุดคือ trades ที่เอามาสุ่มมาจากคนละโลก:

🎯 MC ตอน Train (quick eval) 📊 MC ตอน Backtest
รันเมื่อไหร่ อัตโนมัติทันทีที่เทรนจบ (ต่อท้าย quick eval) ทุกครั้งที่กด Run Backtest / รัน Pipeline
Trades มาจากไหน TradingEnv — โลกอุดมคติ: ปิด position ที่ราคา close, ไม่มี spread/commission/swap/slippage, ไม่มี SL/TP intrabar, ไม่มี lot sizing SimAccount — โลกจริง: costs ครบทุกชั้น, SL/TP เช็คกับ high/low + M1 replay, risk-based lot sizing
Probes ที่รัน Shuffle DD + Skip Retention (SQX-style) Shuffle DD + P(hit hard stop)
คำถามที่ตอบ "recipe นี้ edge กระจายดีไหม คุ้มที่จะ validate ต่อหรือเปล่า" — เครื่องคัดกรองเร็วตั้งแต่ model เกิด "ทุนเท่านี้ + risk เท่านี้ รอดไหม / โดนบังคับหยุดกี่ % ของโลกที่เป็นไปได้" — เครื่องตัดสินใจใช้เงิน
ช่องตั้งค่า หน้า Train → MC Eval Runs (default 1000, 0=ปิด) + MC Skip % (default 10) หน้า Backtest → Risk card → Monte Carlo Shuffles (default 1000, 0=ปิด, ต้องมี ≥10 trades)
ผลเก็บที่ไหน artifacts/models/<name>/<name>.train.json → key quick_eval_mc backtest meta JSON → result.monte_carlo + โชว์ใน Full Report panel
เชื่อตัวเลขได้แค่ไหน ⚠️ DD ที่ได้ ต่ำกว่าจริงเสมอ (ไม่มี costs) — ใช้เปรียบเทียบระหว่าง recipes เท่านั้น ห้ามใช้ตั้งขนาดทุน ✅ ใกล้ความจริงที่สุดใน Python — ตัวเลขนี้แหละที่ใช้ตั้ง risk% / hard stop ก่อนไป MT5 tester + demo
จำง่ายๆ: Train MC = ตาชั่งเปรียบเทียบสูตร ("สูตร A robust กว่าสูตร B ไหม") · Backtest MC = เครื่องวัดความปลอดภัยของเงินจริง ("ทุนหมื่นเหรียญ risk 1% รอดไหม") — ตัวเลขจากตาชั่งเอาไปตั้งขนาดทุนไม่ได้ เพราะชั่งในโลกที่ไม่มีต้นทุน

เหตุผลที่ Skip Retention อยู่ฝั่ง Train: มันวัด "คุณภาพการกระจายของ edge" ซึ่งเป็นคุณสมบัติของ recipe — รู้เร็วได้ตั้งแต่เกิดยิ่งดี ส่วน P(hard stop) อยู่ฝั่ง Backtest เพราะ hard stop เป็นแนวคิดชั้น execution ที่มีความหมาย ก็ต่อเมื่อ costs และ sizing เป็นของจริงแล้วเท่านั้น

5) เกณฑ์การอ่านผล (สรุปรวม)

ตัวเลข มาจาก เกณฑ์ผ่าน ถ้าไม่ผ่าน
Skip retention Train MC ≥ 70% และ P(flip) < 5% edge กระจุก — แก้ features/reward/filter แล้วเทรนใหม่
DD 95% worst-case Backtest MC ≤ 1.5× ของ DD ลำดับจริง และไม่เกิน tolerance ทุน ลด Risk % ต่อ trade
P(hit hard stop) Backtest MC < 5–10% ลด risk หรือขยาย hard DD — ห้าม live จนกว่าผ่าน

ลำดับการใช้ใน workflow:

Train จบ → Train MC ผ่าน (retention ok)     → คุ้มที่จะ validate ต่อ
        → Backtest + realism ครบ (M1/swap)   → ผลจริง
        → Backtest MC ผ่าน (P hard stop ต่ำ) → ขนาดทุน/risk ปลอดภัย
        → Walk-Forward → MT5 real ticks → demo → live

6) ข้อจำกัด และ MC ชนิดอื่นที่ยังไม่ได้ทำ

สมมุติฐานสำคัญ: MC แบบสลับลำดับถือว่า trades เป็นอิสระต่อกัน แต่ตลาดจริงมี clustering — ช่วงแพ้มักกระจุกตาม regime เดียวกัน ตัวเลขจึงเป็น estimate ที่ดี ไม่ใช่คำพยากรณ์ และต้องดูคู่กับ Random Baseline (edge จริงไหม) + Significance (สถิติรองรับไหม) เสมอ
MC ชนิดอื่น (เทียบ SQX) สถานะในระบบ
Shuffle trade order ✅ มี (ทั้ง Train และ Backtest)
Randomly skip trades ✅ มี (ฝั่ง Train — MC Skip %)
Randomize parameters 🟡 เทียบเท่าคือ grid_search + (อนาคต) seed ensemble: เทรน recipe เดิมหลาย seed แล้วดูการกระจาย — ตอบคำถามใหญ่สุดของ RL ว่า "recipe ดีจริง หรือ seed ถูกหวย"
Randomize price data ❌ ยังไม่มี — ใกล้เคียงสุดคือ obs-noise MC (เติม noise ใน features) ซึ่งใน RL เอาไปใส่ตอนเทรนได้เลยด้วย (domain randomization)
