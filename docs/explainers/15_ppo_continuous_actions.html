Explainer 15 · RL internals

PPO ออก "ค่าต่อเนื่อง" ได้อย่างไร — และจะใช้ให้ RL กำหนด SL เองได้ไหม

PPO ไม่ได้ทำนายตัวเลขแบบ regression มันเรียน การแจกแจงความน่าจะเป็นของ action แล้วสุ่มจากมัน สิ่งที่ต่างระหว่าง action แบบเลือกช่อง (discrete) กับแบบตัวเลข (continuous) คือชนิดของการแจกแจงเท่านั้น สูตร PPO เหมือนกันทุกบรรทัด หน้านี้อธิบายกลไก พร้อมตัวทดลองให้ลองดันค่า μ ด้วยมือ และสรุปว่าในโปรเจกต์นี้ต้องแก้อะไรบ้างถ้าจะให้ network ออก "ระยะ SL" เป็นตัวเลข

1. หัวใจของ PPO: มันต้องการจาก policy แค่ตัวเลขเดียว

Policy คือ network ที่รับสถานะ s (หน้าต่าง feature 15 แท่ง + สถานะ position) แล้วให้ π(a|s) = ความน่าจะเป็นที่จะเลือก action a ตอนเทรน agent สุ่ม action จาก π เพื่อสำรวจ แล้ว env ตอบกลับด้วย reward ซึ่งถูกแปลงเป็น advantage (A) = "ดีกว่าที่ critic คาดไว้เท่าไร" จากนั้น PPO ปรับ network ด้วย loss นี้:

ratio = π_new(a|s) / π_old(a|s)          ← ความน่าจะเป็นของ action ที่สุ่มไป เทียบก่อน/หลังอัปเดต
loss  = −min( ratio × A ,  clip(ratio, 1−ε, 1+ε) × A )
state s→ network→ การแจกแจง π(·|s)→ สุ่ม a→ env → reward→ advantage A→ เพิ่ม/ลด π(a|s)

A บวก → ทำให้ action นั้นมีโอกาสถูกเลือกมากขึ้น, A ลบ → น้อยลง ส่วน clip กันไม่ให้ก้าวแรงเกินในหนึ่งรอบ

ประเด็นเดียวที่ต้องจำ: PPO ไม่สนว่า a เป็นเลขจำนวนเต็ม (ช่องที่ 2 = buy) หรือทศนิยม (SL = 1.73 ATR) ขอแค่คำนวณ π(a|s) ได้ ก็เรียนได้ด้วยสูตรเดียวกัน

2. Discrete — ที่โปรเจกต์นี้ใช้อยู่

network ออก logits 4 ตัว (hold / buy / sell / close) → softmax → ได้ความน่าจะเป็น 4 ช่อง (Categorical distribution)

logits  = [ 0.2 , 1.4 , −0.3 , 0.1 ]
softmax = [ 0.17, 0.56, 0.10 , 0.16 ]      ← π(buy|s) = 0.56
ตอนเทรน : จับฉลากตาม prob → อาจได้ sell ก็ได้ (สำรวจ)
ตอน deploy: argmax → buy   (EA ทำ ArgMax(probs) ตรงนี้)

ถ้า buy ที่สุ่มได้มี A = +0.3 → gradient ดัน logit ของ buy ขึ้น ช่องอื่นลงตามสัดส่วน confidence ที่หน้า Analyze ใช้ก็คือ prob ของช่อง argmax นี่เอง

3. Continuous — เปลี่ยนแค่การแจกแจง

แทนที่จะออก logits ของช่อง network ออก μ (ค่ากลาง) และมี σ (ความกว้าง) ประกอบเป็น Gaussian N(μ, σ) action ที่สุ่มได้คือ

a = μ + σ × noise            noise ~ N(0, 1)
π(a|s) = pdf ของ Gaussian ที่จุด a
       = 1/(σ√2π) × exp( −(a−μ)² / 2σ² )
log π(a|s) = −(a−μ)²/2σ² − log σ − ½ log 2π

gradient ของ log π เทียบกับ μ คือ (a − μ)/σ² — นี่คือสาเหตุที่ "มันเรียนได้": ถ้า action ที่สุ่มไป (a) ได้ A บวก μ จะถูกดันเข้าหา a ถ้าได้ A ลบ μ จะถูกดันออกห่างจาก a

Δμ  ∝  A × (a − μ) / σ²

4. ทดลองเอง: ดัน μ ด้วย advantage

สมมติหัว SL ของ network ออก μ = 1.6 ATR, σ = 0.4 กด สุ่ม action เพื่อจับ a หนึ่งค่า แล้วบอกว่า trade นั้นได้ advantage บวกหรือลบ จะเห็น μ ขยับตามสูตร Δμ ∝ A·(a−μ)/σ² (lr = 0.3 เพื่อให้เห็นชัด) ปุ่ม ลด σ จำลองสิ่งที่เกิดเมื่อ ent_coef ต่ำและ policy มั่นใจขึ้น

ยังไม่ได้สุ่ม — กด "สุ่ม action"
สังเกต: ยิ่ง σ แคบ (1) ค่าที่สุ่มได้ยิ่งใกล้ μ = สำรวจน้อยลง (2) ก้าว Δμ ต่อหนึ่ง advantage ยิ่งใหญ่ เพราะหาร σ² → policy ที่มั่นใจมากเกินไปจะเหวี่ยงแรงเมื่อเจอ reward ที่ผิดคาด

5. ตัวอย่างตัวเลขเต็ม ๆ หนึ่งรอบ

  1. สถานะ s (แท่งสัญญาณ SRB ฝั่ง buy) → network ออก μ = 1.6 ATR, σ = 0.4
  2. สุ่มได้ a = 1.9 → env ตั้ง SL = entry − 1.9 × ATR แล้วเดินต่อจน trade ปิด
  3. ผล: trade ได้ reward สูงกว่าที่ critic คาด → A = +0.3
  4. log π(1.9 | s) = −(0.3)²/(2·0.16) − log 0.4 − 0.92 = −0.28 + 0.92 − 0.92 = −0.28
  5. gradient ต่อ μ = (1.9 − 1.6)/0.16 = +1.875 → μ เพิ่ม (ขนาดตาม learning rate และ clip ของ PPO)
  6. รอบถัดไปสถานะคล้ายกัน สุ่มได้ 1.2 → A = −0.2 → gradient = (1.2−1.6)/0.16 × (−0.2) → μ เพิ่มอีก (ออกห่างจาก 1.2)
  7. ทำซ้ำหลายพันครั้ง μ(s) ลู่ไปหาระยะ SL ที่ให้ A สูงสุดในสถานะแบบนั้น และ σ หดเมื่อมั่นใจ
  8. ตอน deploy ไม่สุ่ม: EA ได้ μ(s) = ระยะ SL เป็นตัวเลขจาก network โดยตรง

6. รายละเอียดที่ต้องรู้ก่อนทำจริง

SB3 σ ไม่ขึ้นกับ state

ใน stable-baselines3 PPO (DiagGaussianDistribution) σ เป็นพารามิเตอร์อิสระตัวเดียวทั้ง policy (ตั้งต้นด้วย log_std_init) network เรียนแค่ μ(s) ส่วน σ ค่อย ๆ ลดลงทั่วทั้ง policy ไม่ได้ "กว้างในสถานะที่ไม่แน่ใจ แคบในสถานะที่แน่ใจ"

entropy ent_coef ตัวเดียวคุมสองหัวไม่ได้

entropy ของ Gaussian = log σ + ค่าคงที่ ดังนั้น ent_coef ที่ตั้งไว้สำหรับหัว discrete (0.02) จะไปดันให้ σ กว้างค้าง หรือถ้าต่ำไป σ หดเร็วจนเลิกสำรวจ ต้องแยกน้ำหนักสองหัว

ขอบเขต Gaussian ไม่มีขอบ

สุ่มได้ SL ติดลบหรือ 9 ATR ได้ SB3 แค่ clip ตามขอบ Box (gradient ที่ขอบหาย) ทางที่ถูกคือ tanh squash: a = lo + (hi−lo)·(tanh(u)+1)/2 แล้วแก้ log-prob ด้วย Jacobian − Σ log(1 − tanh²(u)) แบบที่ SAC ทำ

ผสม 2 หัว ต้อง custom policy

SB3 ให้หนึ่งการแจกแจงต่อ policy ถ้าจะมีทั้ง action (Categorical) และ SL (Gaussian) ต้องเขียน ActorCriticPolicy เองที่ถือว่าสองหัวเป็นอิสระ: log π = log π_cat(action) + log π_gauss(SL) และ entropy รวมกัน

credit หัว SL ได้สัญญาณน้อยมาก

SL มีผลต่อ reward เฉพาะ trade ที่ SL "ทำงาน" (โดนหรือเกือบโดน) trade ที่ปิดด้วย close/max_hold ก่อนถึง SL ให้ gradient ≈ 0 แก่หัว SL จาก event SRB ~770 ครั้งในช่วง train จึงเหลือตัวอย่างที่สอนหัวนี้จริง ๆ ไม่กี่ร้อย — คาดว่า μ จะเรียนได้แค่ค่าเฉลี่ย

ทางลัด MultiDiscrete

Categorical 2 ชุด: action 4 ช่อง × SL 5 ช่อง {1.0, 1.5, 2.0, 2.5, 3.0 ATR} SB3 รองรับเอง รวม log-prob ให้ ได้ "เลือก SL ตามสถานะ" เหมือนกัน แค่เป็นขั้น ๆ — ตัวเลือก SL ในงานจริงก็ต่างกันทีละ 0.5 ATR อยู่แล้ว

8. ควรทำเมื่อไร — บันไดที่แนะนำ

ขั้น 1 (ตอนนี้): SL คงที่ 1.5 ATR เป็นกฎใน env (แบบ EA ที่พิสูจน์ OOS แล้ว) + gated entries → RL ตัดสินใจแค่รับ/ข้าม และปิดก่อนเวลา/ถือต่อ
ขั้น 2: manage_6 (breakeven / trailing เป็น action) — ใกล้ runner ของ EA และมีอยู่แล้ว ใช้ต่อเมื่อขั้น 1 ชนะ benchmark
ขั้น 3: MultiDiscrete เมนู SL — เมื่อมี event หลักหลายพัน (หลาย symbol / TF ต่ำกว่า)
ขั้น 4: continuous เต็มรูปแบบ — เมื่อขั้น 3 แสดงว่า SL ที่เลือกตามสถานะต่างจากค่าคงที่จริง ๆ มิฉะนั้นความละเอียดระดับทศนิยมไม่มีอะไรให้เรียน

เหตุผลเชิงข้อมูล: ขั้น B ของการศึกษา SRB (docs/srb_event_edge_2026-10-12.md) แสดงว่า exit แบบง่าย (SL 1.5 ATR + ออกที่ 4 แท่ง) ได้ PF 1.36 ส่วน EA ที่มี 2 ขา + breakeven ได้ 1.55 — โครงสร้าง exit เพิ่มได้นิดเดียว ความซับซ้อนตรงนี้ไม่คุ้มเสี่ยง overfit จาก 770 ตัวอย่าง
