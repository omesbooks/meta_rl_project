Diagnostic · Confidence

Confidence Analysis — หา threshold ที่ model มั่นใจแล้วแม่นจริง

หน้า Analyze ตอบคำถามเดียว: model ทายแม่นขึ้นเมื่อมั่นใจสูงไหม? ถ้าใช่ แปลว่ามี edge ซ่อนอยู่ในบางสถานการณ์ และเราหา confidence threshold ที่คุ้มที่สุดมาใช้เป็น order gate ได้ — บทนี้สอนว่า confidence คำนวณยังไง, อ่านตาราง threshold scan ยังไง และทำไมผลจากหน้านี้ยังไม่ใช่คำตอบสุดท้าย

เป้าหมาย Confidence คืออะไร ขั้นตอนใช้งาน ช่องในหน้า / ไฟล์ที่ใช้ อ่าน Bucket Table อ่าน Threshold Scan Pattern ที่เจอบ่อย ข้อจำกัด ขั้นต่อไป

หน้านี้มีไว้ตอบคำถามอะไร

Question

มั่นใจสูง = แม่นขึ้นจริงไหม

ทุกครั้งที่ model เลือก Buy/Sell มันมีระดับ "ความมั่นใจ" ติดมาด้วย หน้านี้เอา trade ทั้งหมดมาแยกตามความมั่นใจ แล้วดูว่า trade ที่มั่นใจสูงชนะบ่อยกว่าและกำไรดีกว่าจริงหรือเปล่า

Output

ได้ threshold candidate

ถ้าความมั่นใจสัมพันธ์กับความแม่นจริง ระบบจะ scan หา threshold ที่ให้ Profit Factor ดีที่สุด — ค่านี้คือ "ผู้สมัคร" ที่จะเอาไปใส่ช่อง Confidence Threshold ในหน้า Backtest ต่อ

Not a verdict

ยังไม่ใช่ผลตัดสิน

Analyze รันบน TradingEnv โลกอุดมคติ — ไม่มี spread, ไม่มี slippage, ไม่มี swap ตัวเลข PnL ที่เห็นจึงสวยกว่าความจริงเสมอ ต้องยืนยันบนหน้า Backtest ก่อนเชื่อ

Confidence มาจากไหน (และไม่ใช่อะไร)

PPO policy ของเราจบด้วย layer ที่ให้คะแนนดิบ (logits) กับ 4 action: Hold, Buy, Sell, Close จากนั้น softmax แปลงคะแนนเป็นสัดส่วนความน่าจะเป็นที่รวมกันได้ 1 — "confidence" ของ trade คือความน่าจะเป็นของ action ที่ชนะ (argmax prob) เช่น ถ้า Buy ได้ 0.72 และตัวอื่นแบ่งที่เหลือ confidence ของ trade นั้นคือ 0.72 

dist  = model.policy.get_distribution(obs)      # softmax over policy logits
probs = dist.distribution.probs                 # เช่น [0.11, 0.72, 0.08, 0.09]
action     = argmax(probs)                      # 1 = Buy
confidence = probs[action]                      # 0.72
คือ

ระดับความเด็ดขาดของ policy

ค่าสูง = policy ชี้ไปทางเดียวชัดเจน, ค่าต่ำ (ใกล้ 0.25 สำหรับ 4 action) = policy ลังเล แทบจะสุ่ม — มันบอก "ความชัดของการตัดสินใจ" ไม่ใช่โอกาสชนะ

ไม่ใช่

ไม่ใช่ calibrated probability

confidence 0.72 ไม่ได้ แปลว่า trade นี้มีโอกาสชนะ 72% PPO ไม่เคยถูก train ให้ค่านี้ตรงกับ win rate แบบ classifier ที่ calibrate แล้ว — ความหมายของตัวเลขต้องพิสูจน์จากข้อมูล ซึ่งคือหน้าที่ของหน้านี้

พิสูจน์

เชื่อมด้วยหลักฐาน

หน้านี้จับคู่ confidence ตอนเข้า trade กับผล PnL ของ trade นั้นจริง ๆ ทีละไม้ ถ้า model ไหน confidence มีความหมาย มันจะโผล่ในตารางเอง ถ้าไม่มีความหมาย ตารางก็จะฟ้องเหมือนกัน

วิธีอธิบายให้ user เข้าใจง่าย: confidence เหมือน "น้ำเสียง" ตอน model ตอบ — เสียงหนักแน่นไม่ได้แปลว่าถูกเสมอ หน้า Analyze คือการเช็คย้อนหลังว่า model ตัวนี้ เวลาพูดเสียงหนักแน่นแล้วถูกบ่อยขึ้นจริงไหม

กด Analyze

ระบบ load model, auto-detect window size จาก observation space ของ model (ไม่ต้องจำเองว่า train ด้วย window เท่าไร) แล้วเดิน agent ผ่านช่วง test พร้อมบันทึก confidence ของทุก trade ที่เปิด

4

อ่าน 2 ตารางใน Output

ตารางแรก (Confidence Bucket) แยก trade เป็นช่วงความมั่นใจ, ตารางสอง (Threshold Scan) จำลองว่า "ถ้าเทรดเฉพาะตอนมั่นใจ ≥ X" ผลจะเป็นยังไง — ตารางสองคือตัวหลักที่ใช้ตัดสินใจ

5
Verify

เอา threshold ไปยืนยันที่หน้า Backtest

ได้ sweet spot แล้วอย่าเพิ่งเชื่อ — เอาค่านั้นไปใส่ช่อง Confidence Threshold ในหน้า Backtest ที่มี costs, M1 replay, Monte Carlo และ significance test ครบ ถ้ารอดที่นั่นด้วยค่อยถือว่าใช้ได้จริง

ช่องในหน้า Analyze และไฟล์ที่เกี่ยวข้อง

หน้านี้ตั้งใจให้เรียบที่สุดใน dashboard: มีแค่ 2 dropdown กับปุ่มเดียว เพราะค่าอื่นระบบตัดสินใจให้เองหมด

ช่อง / ไฟล์ หน้าที่ หมายเหตุ
Model (dropdown) โมเดล PPO ที่ train สำเร็จแล้ว ระบบ resolve path ของ zip ให้เองผ่าน find_model_path
CSV (dropdown) dataset สำหรับวิเคราะห์ ชุด feature ต้องตรงกับตอน train ไม่งั้นเจอ feature-mismatch error — เลือกไฟล์ที่ใช้ train model ตัวนั้นปลอดภัยสุด
<model>_norm.csv mean/std ตอน train ใช้ normalize feature ให้ scale ตรงกัน หาให้อัตโนมัติ ถ้าไม่เจอระบบหยุดพร้อม error ชัดเจน (ไม่รันต่อแบบผลเพี้ยน)
Window Size ขนาด state window ของ environment auto-detect จาก obs_dim = window × n_features + 3 ของ model — ไม่มีช่องให้กรอกในหน้านี้
ช่วง test ใช้ 20% ท้ายไฟล์ (start fraction 0.8) ช่วงเดียวกับที่ quick eval หลัง train ใช้ จึงเทียบกันได้
Output ตารางผลใน log ของหน้า (ไม่มีไฟล์ output) อยากเก็บผล ให้ copy จาก log — รันซ้ำได้เร็วมากอยู่แล้ว
เบื้องหลัง: ปุ่ม Analyze รัน python rl_analyze.py <model> <csv> — script เดียวกับที่รันจาก command line ได้ และก่อนวิเคราะห์ระบบจะ drop คอลัมน์ที่ชื่อส่อว่า leak อนาคต (future_, next_, target ฯลฯ) ให้อัตโนมัติเหมือนตอน train

ตารางแรก: Performance by Confidence Bucket

ตารางนี้แบ่ง trade ทั้งหมดตามช่วงความมั่นใจ เช่น [0.50-0.60), [0.60-0.70) ... แล้วโชว์จำนวน trade, win rate, PnL เฉลี่ย และ PnL รวมของแต่ละช่วง — ใช้ดู "รูปร่าง" ของความสัมพันธ์ก่อนไปดู threshold scan

คอลัมน์ ความหมาย วิธีใช้
Conf range ช่วงความมั่นใจตอนเข้า trade เช่น [0.60-0.70) ช่วงที่ไม่มี trade เลยจะไม่ถูกพิมพ์ — บอกได้ว่า model กระจุกความมั่นใจแถวไหน
#trades จำนวน trade ในช่วงนั้น bucket ที่มี trade หลักหน่วย อย่าเพิ่งตีความ win rate ของมัน
WinRate / AvgPnL / TotalPnL คุณภาพ trade ของ bucket นั้น รูปที่อยากเห็น: bucket สูงมี WinRate/AvgPnL ดีกว่า bucket ต่ำอย่างเป็นระบบ

ข้อสังเกตที่เจอบ่อย: model ที่ train มาดีมักกระจุก confidence อยู่โซนกลาง-สูง (0.4-0.8) ถ้าเกือบทุก trade อยู่ bucket เดียว แปลว่า policy "เสียงโทนเดียว" — threshold filter จะช่วยอะไรไม่ได้มาก เพราะไม่มีความต่างให้กรอง

ตารางหลัก: Threshold Scan

ตารางนี้จำลองคำถาม "ถ้ายอมเทรดเฉพาะไม้ที่ confidence ≥ X ผลจะเป็นยังไง?" โดยไล่ X ตั้งแต่ 0.30 ถึง 0.90 ทีละ 0.05 แถวไหนทำ Profit Factor สูงสุดเท่าที่เจอมา จะติดดาว ⭐ และดาวดวงสุดท้ายคือ threshold ที่ดีที่สุดของ scan นี้ (แถวที่เหลือ trade ไม่ถึง 30 ไม้ ระบบไม่พิมพ์เลย เพราะสถิติเชื่อไม่ได้)

ตัวอย่างผลจริงจาก model ที่ confidence มีความหมาย — อ่านไล่จากบนลงล่าง:

  Conf>=      #trades    WinRate     TotalPnL         PF
----------------------------------------------------------------------
  >=0.50          115     59.1%       +9.67%        1.45
  >=0.60           90     60.0%       +9.99%        1.66
  >=0.65           71     57.8%       +9.07%        1.80  <- sweet spot
  >=0.70           59     52.5%       +0.98%        1.09  <- edge หาย
1
0.50 → 0.60

ขยับ threshold ขึ้น คุณภาพดีขึ้น

ตัด trade ออก 25 ไม้ (115 → 90) แต่ WinRate ขึ้น, PnL รวมไม่ลด และ PF กระโดด 1.45 → 1.66 — แปลว่าไม้ที่ถูกตัดคือไม้แย่จริง นี่คือสัญญาณว่า confidence กับคุณภาพ trade สัมพันธ์กัน

2
0.65

Sweet spot: PF สูงสุด ก่อนที่ trade จะบางเกิน

ที่ 0.65 เหลือ 71 ไม้ PF ขึ้นถึง 1.80 — สังเกตว่า WinRate ลดนิดหน่อย (57.8%) แต่ PF กลับสูงขึ้น เพราะไม้ที่เหลือ "ชนะครั้งใหญ่ แพ้ครั้งเล็ก" PF จึงเป็นตัวชี้ sweet spot ที่ดีกว่า WinRate เดี่ยว ๆ

3
0.70

เลย sweet spot แล้ว edge หาย

ขยับอีกแค่ 0.05 ทุกอย่างพังพร้อมกัน: WR ร่วงเหลือ 52.5%, PnL เกือบศูนย์, PF 1.09 — ไม้ดี ๆ ถูกกรองทิ้งไปด้วย และ 59 ไม้ที่เหลือเริ่มบางจน noise ครอบ บทเรียนคือ threshold ที่สูงกว่าไม่ได้ดีกว่าเสมอ

ท้ายตาราง ระบบสรุปคำตัดสินให้จากค่า PF ที่ดีที่สุด:

ข้อความสรุป เงื่อนไข ความหมาย
✅ Edge มีจริง best PF > 1.2 ใช้ threshold ที่แนะนำเป็น candidate แล้วไปยืนยันที่หน้า Backtest
🟡 มี edge เล็กน้อย best PF อยู่ระหว่าง 1.0 - 1.2 edge บางมาก — costs จริง (spread/slippage/swap) อาจกินหมด อย่าคาดหวังสูง
❌ ไม่มี edge best PF ≤ 1.0 ทุก threshold confidence filter ช่วย model ตัวนี้ไม่ได้ — ต้องกลับไปแก้ features / instrument / training

Pattern ที่เจอบ่อย และแปลว่าอะไร

Edge จริง

ไต่ขึ้น แล้วร่วง

WR/PF ไต่ขึ้นตาม threshold ถึงจุดหนึ่งแล้วร่วง (เพราะ trades บางเกิน) — รูป "ภูเขา" แบบตัวอย่างข้างบนคือรูปที่ดีที่สุดที่หวังได้ ยอดเขาคือ sweet spot

ไม่มีความหมาย

เส้นแบน

ขยับ threshold แล้ว WR/PF แทบไม่เปลี่ยน = confidence ไม่มีความหมายกับ model นั้น มั่นใจมากหรือน้อยก็แม่นพอ ๆ กัน — ใช้ filter ไปก็แค่ลดจำนวน trade เปล่า ๆ ตั้ง Confidence = 0 ในหน้า Backtest ไปเลยดีกว่า

หลอกตา

สวยเพราะ noise

PF พุ่งเฉพาะแถวที่เหลือ trade น้อย ๆ — sample เล็กทำให้เลขสวิงแรง trade ชนะใหญ่ไม้เดียวก็ดัน PF ขึ้นทั้งแถวได้ อย่าเลือก threshold จากแถวแบบนี้

Sample-size caveat: แถวที่เหลือ trade ต่ำกว่า ~100 ไม้ ให้ถือว่า noise สูง — ตัวเลข WR/PF ของแถวนั้นเปลี่ยนได้มากแค่เพราะ trade 2-3 ไม้พลิกผล ระบบตัดแถวที่ต่ำกว่า 30 ไม้ทิ้งให้แล้ว แต่ช่วง 30-100 ไม้ยังต้องอ่านด้วยความระวัง: ใช้ดูแนวโน้มได้ อย่าใช้ฟันธง

ข้อจำกัดของหน้านี้ (ต้องรู้ก่อนเชื่อผล)

ข้อจำกัด รายละเอียด ผลต่อการตีความ
รันบน TradingEnv โลกอุดมคติ ไม่มี spread, commission, slippage, swap — environment เดียวกับตอน train PnL ทุกตัวในตารางสวยกว่าความจริง ใช้เทียบระหว่าง threshold ได้ แต่อย่าเอาตัวเลขไปอ้างเป็นผลตอบแทนคาดหวัง
นับเฉพาะ entry decision confidence ที่วิเคราะห์คือตอนเปิด position เท่านั้น ไม่รวมจังหวะ Close threshold ที่ได้ใช้เป็น entry gate — หน้า Backtest ก็ใช้แบบเดียวกัน (ไม่ filter Close)
ช่วง test เดียว ใช้ 20% ท้ายไฟล์ ไม่มี walk-forward หลายช่วง sweet spot อาจเลื่อนไปตามช่วงตลาด — Walk-Forward คือด่านที่ตรวจเรื่องนี้
ไม่มี significance test ไม่มี random baseline / Monte Carlo ในหน้านี้ PF 1.8 จาก 71 ไม้อาจเป็นโชค — หน้า Backtest มีเครื่องมือแยกโชคออกจาก edge ให้
Gotcha ที่เจอบ่อยสุด: 0.85 ไม่ใช่ค่าศักดิ์สิทธิ์ — ทุก model มี sweet spot ของตัวเอง model ตัวอย่างข้างบน sweet spot คือ 0.65 และที่ 0.70 edge หายไปแล้ว ถ้าเอา 0.85 ไปใช้กับ model นี้จะแทบไม่เหลือ trade เลย ห้าม copy threshold ข้าม model และห้ามใช้ค่า default โดยไม่ scan ก่อน
Error ที่เจอบ่อย: model/dataset feature mismatch = จำนวน feature ใน CSV ไม่ตรงกับที่ model คาดหวัง (obs_dim หารไม่ลงตัว) — แก้โดยเลือก CSV ที่ใช้ train model ตัวนั้น ไม่ใช่แก้ window ส่วน window size ไม่ต้องกังวลเลย เพราะระบบ auto-detect จาก model ให้แล้ว

ได้ threshold แล้วทำอะไรต่อ

1
Confirm

ยืนยันที่หน้า Backtest ก่อนเชื่อ

เอา sweet spot ไปใส่ช่อง Confidence Threshold ในหน้า Backtest ซึ่งมีของที่หน้านี้ไม่มีครบ: costs จริง, M1 replay สำหรับ SL/TP, Monte Carlo shuffle และ random baseline — ถ้า PF ยังยืนได้หลังหัก costs ค่อยถือว่า threshold นั้นใช้จริงได้

2
Compare

Backtest เทียบ 2 ค่า: 0 กับ sweet spot

รัน Backtest ด้วย Confidence = 0 (baseline ไม่กรอง) และด้วย sweet spot จากหน้านี้ — ถ้าค่า filter แล้ว PF/DD ดีขึ้นจริงในโลกที่มี costs ถึงจะเป็นหลักฐานครบวงจร

3
Robustness

Walk-Forward ด้วย threshold เดิม

ตรวจว่า sweet spot ยังทำงานหลายช่วงเวลา ไม่ใช่ fit กับช่วง test ช่วงเดียว — ถ้า threshold ที่ดีของแต่ละ fold ต่างกันมาก แปลว่ายังพึ่งไม่ได้

4
Fallback

ถ้าเส้นแบนหรือไม่มี edge

อย่าฝืนหา threshold จากตารางที่ไม่มี pattern — ปัญหาไม่ได้อยู่ที่ filter แต่อยู่ที่ตัว model: กลับไปดู features (หน้า Custom Feature), regime ของข้อมูล หรือ train ใหม่

ประโยคสอน user: หน้า Analyze คือ "เครื่องจับโกหก" ของ confidence — มันบอกว่า model ตัวนี้ เวลามั่นใจแล้วเชื่อได้แค่ไหน และควรตั้ง filter ตรงไหน แต่คำตัดสินสุดท้ายว่า threshold นั้นทำเงินได้จริงไหม ต้องไปสอบที่หน้า Backtest ที่มีต้นทุนจริงครบเสมอ
