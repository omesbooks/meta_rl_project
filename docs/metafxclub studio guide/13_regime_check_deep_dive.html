Deep Dive · Regime Detection

Regime Check — อัลกอริทึมข้างในทำงานยังไง และตั้งค่า parameter ยังไง

บทนี้เจาะหน้า Regime Check ลึกกว่าคู่มือหน้า 10: regime คืออะไรในเชิงสถิติ, HMM / K-Means / PELT แต่ละตัวมองตลาดคนละมุมยังไง, และคำตอบของคำถามสำคัญ — แต่ละอัลกอใช้ parameter คนละชุดกัน ไม่ใช่ชุดเดียวกัน

Regime คืออะไร 2 ตระกูลอัลกอ HMM K-Means PELT ตาราง Parameter วิธีอ่านผล + ใช้ต่อ ข้อจำกัด

Regime คืออะไร แล้วทำไม RL ต้องแคร์

"Regime" คือช่วงเวลาที่ พฤติกรรมเชิงสถิติของตลาดคงที่ — ค่าเฉลี่ยการเคลื่อนไหว ความผันผวน และโครงสร้าง trend อยู่ในโหมดเดิมต่อเนื่อง เช่น bull ที่ค่อย ๆ ไต่ / sideways เด้งในกรอบ / panic ที่ vol พุ่งและราคาดิ่ง จุดที่ตลาดสลับโหมด (Lehman 2008, Brexit 2016, Truss mini-budget 2022) เรียกว่า regime break

ทำไมสำคัญกับ RL: PPO เรียนรู้จาก distribution ของ state → action → reward ในข้อมูลเทรน ถ้า dataset คร่อม regime ที่ตายไปแล้ว (เช่น GBP ยุคก่อน Brexit ที่ vol ต่ำและ range แคบกว่าปัจจุบันมาก) โมเดลจะเสียงบ "ความจุสมอง" ไปเรียนพฤติกรรมที่ไม่มีอีกแล้ว — หน้า Regime Check มีไว้ตอบคำถามว่า "ควรตัดข้อมูลเทรนตั้งแต่ตรงไหน" ผ่านปุ่ม Use as Train Cutoff
Input

ใช้แค่ timestamp + close

ทุกอัลกอในหน้านี้อ่านแค่ 2 คอลัมน์จาก CSV — ไม่สน feature อื่นเลย ใช้ dataset ตัวเดียวกับที่จะเทรนได้ทันที ไม่ต้องเตรียมไฟล์พิเศษ

Resample

ยุบเป็น daily ก่อนเสมอ

H4 ถูก resample เป็น close รายวัน (1 จุด/วัน) ก่อนเข้าอัลกอ — เร็วขึ้นหลายเท่าและลด noise ระดับ intraday ที่ไม่เกี่ยวกับ regime

Output

Breakpoints + Match score

ได้ลิสต์วันที่ตลาดเปลี่ยนโหมด + คะแนนว่าจับเหตุการณ์จริง (Lehman/Brexit/Truss หรือ events จาก Gemini) ได้กี่ตัว + chart HTML

อัลกอ 3 ตัว = 2 ตระกูลที่มองปัญหาคนละมุม

ตระกูล 1 · State Assignment

HMM และ K-Means

ติด "ป้ายโหมด" ให้ทุกวันก่อน (วันนี้อยู่ state 0/1/2) แล้วนิยาม break = วันที่ป้ายเปลี่ยน ข้อดีคือได้ทั้ง breakpoints และรู้ด้วยว่าแต่ละช่วงเป็นโหมดอะไร ข้อเสียคือป้ายอาจกระพริบไปมา จึงต้องมี persistence filter กรอง

ตระกูล 2 · Changepoint Detection

PELT

ไม่ติดป้าย แต่มองทั้งเส้นราคาแล้วถามว่า "ถ้าต้องหั่นเส้นนี้เป็นท่อน ๆ ให้แต่ละท่อนมีสถิติภายในนิ่งที่สุด ควรหั่นตรงไหน" — เป็น optimization ที่หาคำตอบ exact ไม่ใช่ประมาณ จึงช้ากว่ามาก

Persistence filter (HMM + K-Means): transition จะถูกนับเป็น break จริง ก็ต่อเมื่อ state ใหม่อยู่ต่อไปอย่างน้อย 25 จาก 30 วัน ถัดไป — กันเคสป้ายกระพริบวันสองวันแล้วเด้งกลับ (flapping) ซึ่งไม่ใช่ regime change จริง ตัวเลขนี้ fix อยู่ในโค้ด ไม่ใช่ช่องให้กรอกใน GUI

ทุก method ให้คะแนนตัวเองด้วย Match score: breakpoint ที่เจอห่างจากเหตุการณ์จริงไม่เกิน ±90 วัน นับเป็น match (เหตุการณ์จริงมาจาก known_events.json ที่ Gemini สร้าง หรือ fallback เป็น Lehman/Brexit/Truss ที่ hardcode ไว้)

HMM 3-state ⭐ (ตัวแนะนำ — default)

แนวคิด

Hidden Markov Model ตั้งสมมติฐานว่าตลาดมี "สถานะซ่อนเร้น" ที่เรามองไม่เห็นตรง ๆ เห็นได้แค่ ผลของมัน — เหมือนอยู่ในห้องไม่มีหน้าต่าง แต่เดาได้ว่าข้างนอก ฝนตกหรือแดดออกจากการดูคนที่เดินเข้ามาว่าตัวเปียกไหม HMM ทำ inference ย้อนกลับ: จาก return + volatility รายวัน คำนวณว่าแต่ละวัน "น่าจะ" อยู่ state ไหนที่สุด

สิ่งที่มันเห็นจริง ๆ

Observation ต่อวันคือเวกเตอร์ 2 ตัว:

obs[วัน i] = [ log_return รายวัน,  rolling std 20 วันของ % change ]

model = GaussianHMM(n_components=n_states,   # <- ช่อง "States" ใน GUI
                    covariance_type="diag",
                    n_iter=100, random_state=42)
states = model.fit(obs).predict(obs)          # ป้าย state ต่อวัน
break  = วันที่ states[i] != states[i-1] และผ่าน persistence filter

การใช้คู่ [return, vol] ทำให้ HMM แยกโหมดจาก joint distribution — เช่น "ขึ้นช้า vol ต่ำ" (bull เนียน ๆ) กับ "ลงแรง vol สูง" (panic) เป็นคนละ state กันชัดเจน แม้ราคาเฉลี่ยจะใกล้กัน นี่คือเหตุผลที่มันเก็บครบ 3/3 events ในการทดสอบ (ดีสุดใน 6 methods ที่เคยเทียบ) และใช้เวลาแค่ ~3 วินาที

Parameter เดียวที่ต้องกรอก: States

ค่าความหมาย / ผลที่ตามมา
3 (default ⭐) ตีความง่ายสุด: bull / bear / sideways — ผ่านการทดสอบกับ forex H4 มาแล้ว เริ่มที่ค่านี้เสมอ
2 หยาบลงเหลือ calm / panic — break น้อยลง เหมาะถ้าอยากเห็นเฉพาะ วิกฤติใหญ่จริง ๆ
4–5 ละเอียดขึ้น แต่ state เริ่มซ้ำความหมายกัน (bull อ่อน/bull แรง) → transition ถี่ขึ้น, break เยอะเกินใช้งาน และ fit ไม่เสถียรขึ้นเรื่อย ๆ
อย่าลืม: จำนวน state ไม่ใช่ "ยิ่งเยอะยิ่งแม่น" — เป้าหมายของหน้านี้คือหา cutoff ไม่กี่จุด ไม่ใช่จำแนกตลาดให้ละเอียดที่สุด

K-Means rolling (ตัวเร็ว)

แนวคิด

ไม่มีโมเดลความน่าจะเป็นอะไรเลย — แค่สร้าง "รูปพรรณ" ของแต่ละวันจากหน้าต่างย้อนหลัง แล้วจับกลุ่มวันที่หน้าตาคล้ายกันเข้า cluster เดียวกัน: 

รูปพรรณ[วัน i] = [ rolling mean(win),    # ราคาเฉลี่ยช่วงหลัง
                   rolling std(win),      # ความผันผวนช่วงหลัง
                   slope = diff(win)/win ] # ความชันของ trend

labels = KMeans(n_clusters=k, random_state=42).fit_predict(รูปพรรณ)
break  = วันที่ labels เปลี่ยน และผ่าน persistence filter เดียวกับ HMM

ต่างจาก HMM ตรงที่ K-Means ไม่รู้เรื่องลำดับเวลา — มันไม่รู้ว่าวันนี้มาหลังเมื่อวาน แค่ดูว่าช่วง win วันหลังสุด "หน้าตา" เข้ากลุ่มไหน ข้อแลกคือเร็วมาก (~60ms) แต่จับเหตุการณ์ได้ 2/3 ในการทดสอบ — เหมาะไว้รันเช็คไว ๆ ก่อนยิง HMM ยืนยัน

Parameter 2 ตัว: Clusters (k) และ Window (days)

ParameterDefaultวิธีคิดตอนปรับ
Clusters (k)3 ความหมายเดียวกับ States ของ HMM (จำนวนโหมดตลาด) — แต่เป็นคนละช่องกรอกกัน ค่าที่ใส่ให้ HMM ไม่ได้ถูกส่งมาที่นี่
Window (days)60 ความยาวหน้าต่างที่ใช้สร้างรูปพรรณ · สั้น (20–30) = ไวต่อการเปลี่ยนแต่ noise เยอะ break ถี่ · ยาว (90–120) = นิ่งแต่รู้ตัวช้า (lag โดยประมาณ ≈ ครึ่งหนึ่งของ window)

PELT (ตัวเป๊ะแต่ช้า)

แนวคิด

PELT (Pruned Exact Linear Time) แก้โจทย์ optimization ตรง ๆ: หั่นเส้นราคาเป็นกี่ท่อนก็ได้ โดยจ่าย "ค่าปรับ" (penalty) ทุกครั้งที่หั่นเพิ่ม 1 จุด แล้วหาคำตอบที่ ผลรวมของความไม่นิ่งภายในแต่ละท่อน + ค่าปรับรวม ต่ำที่สุด 

ต้นทุนรวม = Σ cost(segment ที่ j)  +  penalty × จำนวนจุดหั่น
                  ↑ ใช้ RBF kernel: จับการเปลี่ยนของ "distribution ทั้งก้อน"
                    ไม่ใช่แค่ค่าเฉลี่ยขยับ (จับ vol shift ได้ด้วย)

algo = ruptures.Pelt(model="rbf").fit(daily_close)
breaks = algo.predict(pen=penalty)   # <- ช่อง "Penalty" ใน GUI

จุดขายคือคำตอบเป็น global optimum แบบ exact ไม่ใช่การไล่หาแบบ greedy — แลกกับเวลาเป็นหลักนาทีบนข้อมูล 10+ ปี (เทียบกับ ~3s ของ HMM) ผลทดสอบ 2/3 events

Parameter เดียว: Penalty — และมันทำงานกลับด้านกับที่หลายคนเดา

Penaltyผล
ต่ำ (10–20) หั่นถี่ — จับ shift เล็ก ๆ ด้วย ได้ break เป็นสิบจุด ส่วนใหญ่ไม่ใช่ regime จริง
50 (default) สมดุลที่ทดสอบมากับ forex daily 10+ ปี — ได้ break หลักหน่วย
สูง (100–200) หั่นเฉพาะ shift ใหญ่มาก — เหลือเฉพาะวิกฤติระดับ Lehman/COVID
วิธีจูนที่แนะนำ: เริ่ม 50 → ถ้า break เยอะจนอ่านไม่ไหว คูณสอง (100, 200) → ถ้าไม่เจออะไรเลย หารสอง (25, 10) Penalty ไม่ได้กำหนดจำนวน break ตรง ๆ (ไม่เหมือน BinSeg ใน CLI ที่สั่ง n_bkps=3 ได้เลย) — มันกำหนด "ความคุ้มค่า" ของการหั่นแต่ละครั้งแทน

สรุปตรงคำถาม: แต่ละอัลกอใช้ parameter ชุดเดียวกันไหม → ไม่

Auto-update events ด้วย Gemini

เหตุการณ์อ้างอิงตั้งต้นมีแค่ 3 ตัว (Lehman/Brexit/Truss — เหมาะกับ GBP) ถ้าใช้คู่เงินอื่นให้กดปุ่ม Gemini refresh: ระบบจะ auto-detect price shocks ใน dataset แล้วให้ Gemini ระบุว่าแต่ละ shock คือเหตุการณ์อะไร ผลถูกเก็บใน known_events.json และใช้แทนชุด hardcode ทันที (ต้องใส่ Gemini API key ใน Settings ก่อน)

Use as Train Cutoff

เลือก breakpoint แล้วกดปุ่มนี้ → ระบบสร้าง dataset ใหม่ที่ตัดข้อมูลก่อน break ทิ้ง (ไฟล์ลงท้าย _from_YYYY-MM-DD) เอาไปเข้าหน้า Train ได้เลย — และไฟล์ที่ตัดแล้วยังสืบทอดไฟล์ M1 คู่ของต้นฉบับโดยอัตโนมัติ (ระบบ backtest ตามหา M1 จากชื่อบรรพบุรุษให้เอง)

เทคนิคเพิ่มความมั่นใจ: รัน 2–3 methods แล้วดูว่า breakpoint ล่าสุดตกที่ช่วงเดียวกัน (±1–2 เดือน) ไหม — ถ้า HMM กับ K-Means ชี้จุดเดียวกัน ทั้งที่มองตลาดคนละมุม นั่นคือสัญญาณว่า break นั้นจริง ไม่ใช่ artifact ของอัลกอ

ข้อจำกัดที่ต้องรู้ก่อนใช้

Retrospective เท่านั้น

มันบอกอดีต ไม่ใช่ปัจจุบัน

ทุก method วิเคราะห์ข้อมูลย้อนหลังทั้งก้อน — HMM/K-Means ยังต้องรอ persistence 30 วันกว่าจะยืนยัน break ได้ แปลว่าโดย design มันรู้ regime change ช้าอย่างน้อย 1 เดือน ใช้กำหนด cutoff ได้ แต่ใช้เป็นสัญญาณเทรด realtime ไม่ได้

Daily resolution

ไม่เห็น shift ระดับ intraday

เพราะยุบเป็น daily ก่อน regime ที่เปลี่ยนเฉพาะบาง session (เช่น Asia นิ่งลงแต่ London เหมือนเดิม) จะมองไม่เห็น — สำหรับ H4 model เรื่องนี้ยอมรับได้ แต่ต้องรู้ว่า trade-off อยู่ตรงไหน

Break ≠ ต้องตัดเสมอ

บาง regime วนกลับมาซ้ำ

ถ้าตลาดสลับไปมาระหว่างโหมดเดิม ๆ (mean-reverting ระหว่าง 2-3 states) การตัดข้อมูลทิ้งตั้งแต่ break ล่าสุดอาจโยนตัวอย่างดี ๆ ทิ้ง — ตัดเมื่อ regime เก่า "ตายแล้วไม่กลับมา" (structural change เช่น Brexit) ไม่ใช่ทุกครั้งที่เห็นเส้นแดง
