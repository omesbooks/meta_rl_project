วิธีอ่านกราฟ Monte Carlo ทีละค่า

คู่มืออ่านกราฟ MC ในหน้า Backtest แบบชี้ทีละองค์ประกอบ: แผงพัดด้านบนบอก "ระหว่างทางเจ็บได้แค่ไหน" แผง histogram ด้านล่างตัดสิน PASS / CAUTION / FAIL ให้เลย — ตัวอย่างประกอบใช้ตัวเลขจริงจาก rl_uj_extra (300 shuffles)

ภาพรวม 2 แผง แผงบน: เส้นทุกเส้น ตัวเลขทุกตัว แผงล่าง: เกณฑ์ตัดสิน อ่านเส้นส้ม เช็คลิสต์ 5 ข้อ กับดักที่ต้องรู้

แผงบน · Fan Chart

"ไม้ชุดเดิม ดวงเรียงต่างไป หน้าตาเป็นยังไง"

ระบบเอา trade ทั้งหมดจาก backtest มาสลับลำดับสุ่ม (เหมือนสับไพ่) ตามจำนวนที่ตั้งใน Monte Carlo Shuffles แล้ววาดเส้นทุน ของทุกการสับซ้อนกัน — ความกว้างของพัดคือ "ช่วงชะตากรรมที่เป็นไปได้"

แผงล่าง · Verdict

"มีกี่โลกที่พาพอร์ตชนเส้นตาย แล้วผ่านเกณฑ์มั้ย"

เก็บค่า Max Drawdown ของทุกโลกมาเรียงเป็น histogram เทียบกับเส้น hard stop แล้วสรุปผลเป็น PASS / CAUTION / FAIL บนหัวกราฟพร้อมสี — ไม่ต้องตีความเอง

กติกาฟิสิกส์ของกราฟนี้: การสลับลำดับไม่เปลี่ยนกำไรรวม (คูณสลับที่ได้) → ทุกเส้นหุบมาจบจุดเดียวกันเสมอ อย่าตกใจว่าทำไมปลายพัดรวบ — สิ่งที่ต้องอ่านคือ "ระหว่างทาง" ไม่ใช่ปลายทาง

แผงบน — องค์ประกอบทีละเส้น

องค์ประกอบ มันคืออะไร อ่านยังไง
เส้นเทาจาง ๆ (spaghetti) เส้นทุนของทุก shuffle — ตั้ง 300 ก็วาด 300 เส้น ความโปร่งใสปรับอัตโนมัติ ตรงไหนเข้ม = เส้นผ่านหนาแน่น = โซนที่เกิดบ่อย · เส้นเดี่ยว ๆ ที่หลุดขอบ = เคสสุดขั้วที่หายาก
แถบฟ้าอ่อน (5–95% envelope) ที่แต่ละลำดับ trade — 90% ของทุกโลกอยู่ในแถบนี้ ใช้เป็น "ขอบเขตปกติแบบกว้าง" — อะไรที่หลุดนอกแถบคือ 10% สุดขั้ว
แถบฟ้าเข้ม (25–75% envelope) ครึ่งกลางเป๊ะของทุกความเป็นไปได้ "โซนคาดหวัง" — ถ้าไป live แล้ว equity เกาะโซนนี้ = เป็นไปตามคาด
เส้นฟ้าประ (median path) เส้นทางตัวแทนตรงกลางสุดของทุก shuffle ใช้เป็น "ตัวแทนที่แฟร์" ของระบบ แทนที่จะยึดเส้นจริงที่อาจโชคดี/ร้าย
เส้นส้มหนา (actual order) ลำดับจริงตามเวลาจาก backtest ของคุณ ดูว่าอยู่ส่วนไหนของพัด — รายละเอียดใน หัวข้ออ่านเส้นส้ม
เส้นเทาประแนวนอน ทุนเริ่มต้น (เช่น $10,000) เส้นแบ่งกำไร/ขาดทุน — พัดที่ลอยเหนือเส้นนี้ทั้งพัด = ทุกโลกจบบวก
เส้นแดงประ (safety line) ระดับ hard stop คิดจากทุนเริ่มต้น เช่น 15% → $8,500 เส้นตาย — ถ้ามีเส้นเทาเส้นไหนจุ่มลงแตะ = โลกใบนั้นโดนบังคับหยุดเทรด
แกน X — Trade # ลำดับไม้ที่ 1, 2, 3, … ไม่ใช่เวลา เส้น shuffle ไม่มี timestamp ของตัวเอง จึงเทียบกันด้วยลำดับไม้
แกน Y — Equity ($) มูลค่าพอร์ต ทบต้นตามกำไร % ของแต่ละไม้ พัดโค้งขึ้นแบบเร่งตัวเป็นเรื่องปกติของ compounding ไม่ใช่สัญญาณพิเศษ

ตัวเลขทุกตัว — นิยาม + ตัวอย่างจริงจาก rl_uj_extra

ค่า ตัวอย่างจริง ความหมายตรง ๆ
N order shuffles 300 จำนวนโลกทางเลือกที่จำลอง = ค่าที่ตั้งในช่อง Monte Carlo Shuffles — ยิ่งเยอะ histogram ยิ่งเนียน (1000 คือค่าแนะนำ, 300 ยังหยาบอยู่บ้าง)
median (DD) −5.4% ครึ่งหนึ่งของทุกโลกเจ็บไม่เกิน −5.4% — นี่คือ "DD ที่ควรคาดหวัง" แทนที่จะยึด DD ของลำดับจริงเส้นเดียว
95% worst −8.3% มีเพียง 5% ของโลกทั้งหมดที่เจ็บลึกกว่า −8.3% — ใช้ค่านี้วางแผนเงิน: "เตรียมใจรับ DD ราว 8%" ไม่ใช่ 5%
hard stop −15% เพดานขาดทุนที่ยอมรับได้ (ตั้งผ่าน --hard_dd) — DD ที่ทะลุค่านี้ = ถือว่าพอร์ตตาย
P(hit hard stop) 0.0% ตัวเลขสำคัญที่สุดในกราฟ — สัดส่วนโลกที่ DD ทะลุ hard stop: 0.0% = ใน 300 โลก ไม่มีใครตายเลย · ถ้าเป็น 16% = ไม้ชุดเดียวกันนี้ ตายไป 48 จาก 300 โลก ทั้งที่ลำดับจริง "รอด"
ทำไมต้องดู median แทน DD จริง: DD ของ backtest จริง (เช่น −8.11%) คือผลของลำดับใบเดียว — ถ้ามันต่ำกว่า median มาก แปลว่าลำดับจริงแค่โชคดี ตอนไป live ควรคาดหวังตามการกระจาย (median ถึง 95% worst) ไม่ใช่ตามเส้นเดียว

แผงล่าง — histogram + เกณฑ์ตัดสิน

แต่ละแท่งคือ "จำนวนโลก" ที่ Max DD ตกในช่วงนั้น เช่น แท่งสูงสุดแถว −5% หมายถึงโลกส่วนใหญ่เจ็บลึกราว 5% — แล้วอ่าน 3 เส้นแนวตั้ง:

  • ฟ้าประ = median — จุดกึ่งกลางการกระจาย
  • ส้มประ = 95% worst — ขอบเคสร้าย
  • แดงประ = hard stop — เส้นตาย

เกณฑ์ตัดสิน (ระบบสรุปให้บนหัวกราฟพร้อมสี)

Verdictเงื่อนไขความหมาย
PASS P(hit hard stop) < 5% เสี่ยงเชิงลำดับต่ำ — ขนาด risk/trade ที่ใช้อยู่ปลอดภัยกับ trade ชุดนี้
CAUTION 5% – 10% ก้ำกึ่ง — ควรลด risk/trade ลง หรือยอมรับว่ามีโอกาส 1 ใน 10-20 ที่จะโดนหยุด
FAIL > 10% อย่าเพิ่ง live — ลด risk/trade แล้วรัน backtest ใหม่จน P ต่ำกว่าเกณฑ์

วิธีอ่านด้วยตาโดยไม่ต้องดูตัวเลข: ดูช่องว่างระหว่าง "ก้อน histogram" กับ "เส้นแดง" — ตัวอย่าง rl_uj_extra: ก้อนกระจุกช่วง −4% ถึง −9% ส่วนเส้นแดงอยู่ −15% ห่างกันมาก = ปลอดภัยชัดเจน · เมื่อไหร่ที่หางก้อนเริ่มลามทับเส้นแดง = สัญญาณอันตราย

อ่านตำแหน่งเส้นส้ม (ลำดับจริง) — บอกนิสัยของ model

ตำแหน่งเส้นส้มตีความ
วิ่งกลางพัด ใกล้ median ลำดับจริงเป็นตัวแทนที่ดี — ตัวเลข backtest เชื่อถือได้ตามที่เห็น
วิ่งขอบบน / หลุดเหนือพัด ลำดับจริง "โชคดี" กว่าค่าเฉลี่ย — ผลจริงตอน live มีแนวโน้มต่ำกว่า backtest ให้ยึด median เป็นความคาดหวังแทน
วิ่งขอบล่าง / จุ่มใต้พัด ลำดับจริง "โชคร้าย" กว่าค่าเฉลี่ย — ระบบอาจดีกว่าที่ backtest โชว์
สลับข้าง เช่น ใต้พัดช่วงต้น → เหนือพัดช่วงปลาย (แบบ rl_uj_extra ในภาพ) กำไรกระจุกตามช่วงเวลา (regime clustering) — trade ไม่ได้อิสระต่อกันจริง แปลว่าตอน live อาจเจอช่วงแห้งแล้งยาวกว่า ที่พัดบอก เพราะ MC เกลี่ยช่วงแย่กระจายทิ้งไปแล้ว

เช็คลิสต์อ่านกราฟใน 10 วินาที

  1. พัดชี้ขึ้นมั้ย? — ปลายพัดสูงกว่าทุนเริ่มต้น = ทุกลำดับจบกำไร
  2. Verdict สีอะไร? — เขียว PASS / ส้ม CAUTION / แดง FAIL (แผงล่าง)
  3. ก้อน histogram ห่างเส้นแดงแค่ไหน? — ยิ่งห่างยิ่งปลอดภัย
  4. พัดแคบหรือบาน? — แคบ = ระบบนิ่ง · บานมาก = ผลขึ้นกับดวงเยอะ
  5. เส้นส้มอยู่ส่วนไหนของพัด? — กลาง = เชื่อ backtest ได้ · ขอบ/นอกพัด = ปรับความคาดหวังไปที่ median

กับดักที่กราฟสวยก็ช่วยไม่ได้

กับดัก 1

In-sample trap — กับดักที่เจอบ่อยสุด

MC ประเมิน "trade ชุดที่ป้อนเข้ามา" — มันไม่รู้ว่า trade นั้นมาจากข้อมูลที่ model เคยเห็นตอนเทรนหรือเปล่า ถ้า backtest รันทับช่วง train (Skip = 0) พัดจะสวยหลอก ๆ → ตั้ง Skip % ให้พ้นช่วง train ก่อนเสมอ (เช่น 85)

กับดัก 2

MC สมมติว่า trade อิสระต่อกัน

ตลาดจริงแพ้/ชนะเป็นช่วงตาม regime — การสับไพ่ทำลาย clustering นั้นทิ้ง ผลคือ DD ที่ประเมินได้มัก "มองโลกดีเกินไปเล็กน้อย" ใช้แถบเป็น floor ของความเสี่ยง ไม่ใช่เพดาน

กับดัก 3

ปลายทางเดียวกัน ≠ การันตีกำไร

ทุกเส้นจบจุดเดียวกันเพราะคณิตศาสตร์ของการสลับลำดับ ไม่ใช่เพราะระบบเก่ง — คำถามว่า "กำไรนี้จริงมั้ย" ต้องดูจาก Random Baseline + Significance + OOS test ไม่ใช่จากกราฟนี้

กับดัก 4

Shuffles น้อย = ตัวเลขหยาบ

300 shuffles อ่าน P(hard stop) ได้ละเอียดสุดแค่ 0.33% ต่อสไลซ์ และ histogram เป็นหยัก ๆ — ใช้ 1000 ขึ้นไปเมื่อจะตัดสินใจจริง (ต้นทุนเวลาคำนวณเพิ่มไม่กี่วินาที)
