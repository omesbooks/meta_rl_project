# SRB features in RL — Python-first A/B (2026-10-12)

Question: if the SRB breakout event (`docs/srb_event_edge_2026-10-12.md`: ~+0.15 R per
event, short 1–8 bar edge) is handed to PPO as plain input columns, does the agent use it?

## Setup

- Data: `tools/data/build_srb_h1_dataset.py usdjpy_tds_h1.csv usdjpy_tds_h4.csv --out usdjpy_tds_h1 --start 2015-01-01`
  → 72,717 H1 bars (RoboForex `USDJPY_TDS`, 2015-01 → 2026-09). Split 70/15/15:
  Train → 2023-03-01, Validation → 2024-11-29, Test 2024-11-29 → 2026-09-02 (252 SRB events).
- Arms, identical rows: **base** = 28 plain per-bar features (returns, ATR, candle shape,
  EMA distance/slope, RSI, rolling-extreme nearness 24/120/240, lag-safe fractals, hour/dow,
  sessions) · **+SRB** = base + 13 SRB columns (`srb_sig` ±1, age, zone distances/room/touches,
  break flags, zone counts).
- `tools/analysis/obs_ablation.py --arms C --seeds 0,1,2 --steps 200000 --max_hold 24 --spread_pct 3.8e-5 --commission 0`
  (window 15, no pruning, balanced reward, basic_4, 1 pip round-trip; backtest `pure_agent`, no SL,
  best checkpoint on Validation). ~21 min per seed.

## Result (Test slice, PF with 95% bootstrap CI)

| arm | feats | seed 0 | seed 1 | seed 2 | pooled PF | seeds with CI lo > 1 |
|---|---:|---|---|---|---:|---:|
| base | 28 | 1.03 [0.86, 1.23] | 1.04 [0.85, 1.26] | 1.10 [0.90, 1.31] | 1.05 | 0/3 |
| +SRB | 41 | 0.92 [0.77, 1.08] | 0.98 [0.83, 1.17] | 0.79 [0.65, 0.96] | 0.89 | 0/3 |

Benchmark the agent had to beat on the same Test rows (every SRB signal, no stop, 1 pip):
exit after 4 bars → PF 1.35, +0.126 R/trade, +1,077 pips over 252 trades; after 8 bars → PF 1.33.
Validation slice for the same rule: PF 0.93 (the event has no edge there — best-model selection is noisy).

## Why: the agent never used the signal

Entries of each model vs the SRB signal bars (random expectation: 2.4% of entries on a
signal bar, 50% in the signal's direction):

| model | trades | on-signal entries | same direction | PF on-signal / other | mean hold |
|---|---:|---:|---:|---|---:|
| +SRB s0 | 1,500 | 2.9% (44) | 41% | 1.80 / 0.90 | 4.9 |
| +SRB s1 | 1,180 | 2.3% (27) | 52% | 0.72 / 0.99 | 6.5 |
| +SRB s2 | 1,365 | 2.3% (31) | 52% | 0.65 / 0.79 | 5.3 |
| base s0–s2 | 1,111–1,253 | 1.3–3.8% | 23–62% | — | 5.3–6.3 |

Every model trades 1,100–1,500 times on an 11k-bar slice (one trade per 7–9 bars, held ~5 bars)
and enters on signal bars no more often than chance, in a random direction. The 13 extra columns
only added noise (618 inputs vs 423): the +SRB arm is worse than base on all three seeds.

Conclusion: a sparse event (2.4% of bars) given as a feature is not found by PPO under a
per-bar reward with an idle penalty; the agent converges to frequent short trades regardless.
Adding the EA's feature block to the collector would not change this.
